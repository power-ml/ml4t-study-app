# ML Domain 5 — Dyna & Model-Based Reinforcement Learning

## Domain cheat-sheet

- **Model-free vs. model-based control.**
  - **Model-free** methods (plain Q-learning, Sarsa) learn action values *directly* from observed transitions. They need **no explicit model** of the environment's dynamics — each real transition `(s, a, r, s')` drives one value update and is then discarded.
  - **Model-based** methods *also learn a model* of the environment and use it to generate experience internally. **Dyna** is the canonical integrated architecture: it learns values *and* a model, and uses the model to **plan** between real interactions.
- **The learned model = transitions + rewards.** A model answers "if I take action `a` in state `s`, what next state `s'` and reward `r` will I see?"
  - **Transition model `T(s, a)`** predicts the next state (a single next-state for a *deterministic* environment, or a *distribution* over next states for a *stochastic* one).
  - **Reward model `R(s, a)`** predicts the immediate reward. Transition and reward predictions are **separate** components — a model can store `s'` without `r` (or vice versa), and the two can differ in accuracy. The reward is *not* automatically specified by the transition model unless rewards are explicitly stored.
  - A model is **learned from direct experience**: it is only as good as the observations behind it. Unobserved `(s, a)` pairs are unknown; inventing a default next-state (e.g., "state 0") injects bias.
- **Direct experience vs. simulated experience.**
  - **Direct (real) experience** comes from actually interacting with the environment — the only source of *new* information about the world.
  - **Simulated experience** is generated by the learned model. It is a **prediction** based on prior observations, **not** a fresh observation of the environment and **not** an independent real-world sample. Model samples reuse learned assumptions; they do not add new evidence.
  - **Dyna applies the same value-update logic to both** sources: a Q-learning backup `Q(s,a) ← Q(s,a) + α[r + γ·max_a' Q(s',a') − Q(s,a)]` works identically whether `(r, s')` came from the environment or the model.
- **Acting, learning, planning (the Dyna-Q loop).** Each real step: (1) **act** — take an action in the environment and observe `(r, s')`; (2) **direct RL** — update `Q` from that real transition; (3) **model-learning** — store/refresh the model with the observed transition; (4) **planning** — run `n` ( `dyna` ) simulated backups: sample previously observed `(s, a)` pairs, query the model for `(r, s')`, and apply the *same* Q-update.
  - **Acting** changes/samples the external environment; **planning** reasons purely with the internal model — no environment interaction.
  - `dyna = n` sets the **number of planning updates per real step**; `dyna = 0` removes planning but **leaves the direct update intact** (reduces to ordinary Q-learning). More planning = more computation between real interactions, not more real data.
  - Planning can update `(s, a)` pairs **not** visited on the current real step, as long as they exist in the model — this is how Dyna reuses experience.
- **Why planning helps: value propagation & sample efficiency.**
  - **Backups chain information through modeled links**: once a terminal/goal reward is discovered, replaying predecessor transitions carries that value *backward* through the chain without physically re-traversing it. Bootstrapping uses the successor's *current* `Q` estimate, so a single update rarely makes upstream values optimal — many backups may be needed.
  - **Sample efficiency**: Dyna extracts *many* value updates from the information in a *fixed* set of real interactions, reaching a target policy with **fewer** costly real samples. This matters most when real trials are **slow, risky, or expensive** (robotics, clinical, live trading).
  - **Sample efficiency ≠ computational efficiency**: planning saves *environment interaction* but *consumes computation*. When the real environment/simulator is itself cheap to query, the advantage of learning a separate model shrinks.
- **Model error and planning bias.** Planning only propagates what the model contains.
  - A **last-observation** model collapses a stochastic outcome into a single deterministic one — it misrepresents the true distribution. A **probabilistic/count-based** model stores multiple outcomes and their frequencies and can sample different next states across updates.
  - **Planning amplifies model error**: thousands of backups on a biased model repeatedly reinforce that bias (e.g., omitted transaction costs make frequent trading look profitable; an underestimated tail-loss looks ever more attractive). More planning does **not** correct a missing component — repetition cannot supply information absent from the model.
  - **Nonstationarity**: when dynamics change (a bridge closes), the old model is **stale**; planning can strengthen an obsolete route. Only **new direct experience** can expose the change and correct the model. Rare events absent from a small sample are not proven impossible — they may simply be unobserved.
- **Deterministic vs. stochastic environments.**
  - **Deterministic & stationary**: one stored next-state + reward per observed pair represents the dynamics *exactly*; planning replays with no outcome sampling. But determinism does **not** reveal unvisited pairs, and it does **not** make every policy optimal — good and bad actions still exist.
  - **Stochastic**: normalized outcome counts estimate a categorical transition distribution; a single simulated draw is *one outcome*, not the distributional expectation. More representative real observations improve the estimates.

## Common traps

- **Inverted-polarity questions (9 of 21 here).** When the body says "mark each statement True when the stated claim is **incorrect** and False when it is correct," the Answer Key verdict is flipped relative to the statement's truth: **True = the statement is wrong; False = the statement is accurate.** Read the polarity line *first*. Inverted here: **G1Q1, G2Q2, G3Q2, G3Q3, G4Q1, G4Q2, G5Q1, G6Q2, G7Q2.** The other 12 are Normal (True = accurate).
- **"Planning executes the action again."** False — planning updates occur **internally** from the model; the agent does **not** re-execute sampled actions in the environment.
- **"A model-generated transition is a new real observation."** False — it is a *prediction* from prior data, not a fresh environmental outcome, and not an independent real-world sample. 50 planning transitions are **not** 50 new market observations.
- **"Dyna needs a model before it can update from a real transition."** False — direct Q-learning updates from the observed transition *without* any model; the model is only needed for planning. Agent X (model-free) is a legitimate learner.
- **"The transition model also gives the reward."** False — reward info must be stored separately unless explicitly folded into the model. Storing a reward estimate does **not** remove the need for the next state in the bootstrapped TD target.
- **Last-outcome ≈ true distribution / expectation.** False — storing the most recent next-state (or reward) discards the probabilities; it is **not** the 70/30 distribution and **not** the mean. A last-reward model returns the last value seen, not the expectation.
- **"More planning always improves the policy / corrects the model."** False — planning on a biased or stale model **amplifies** the error; repetition cannot inject a missing outcome, cost, or dynamics change. Only new direct experience can.
- **"Dyna guarantees a better policy / outperforms the direct learner every run."** False — outcomes depend on model fidelity, sampling, parameters, and randomness; an inaccurate model can *degrade* learning.
- **"Simulated experience makes real observations unnecessary."** False — real interaction is still needed to build, correct, and refresh the model, especially for rare/unseen outcomes and nonstationary dynamics.
- **"Uniform sampling guarantees coverage/accuracy."** False — sampling *with replacement* can miss most pairs and repeat others; coverage does not establish correctness. **Prioritized** sweeping (large prediction errors first) focuses computation on surprising, relevant changes and speeds propagation; planning *order* matters.
- **"`dyna = 0` removes the direct update."** False — it removes only *planning*; the direct Q-learning update remains (ordinary Q-learning).
- **Sample efficiency = free / no uncertainty.** False — planning conserves *samples* but spends *computation*, and model uncertainty matters **most** precisely when direct samples are scarce.
- **Absence of a rare event ⇒ probability zero.** False — a 1% penalty can be absent from 50 observations yet still occur; the model simply has not learned it.
